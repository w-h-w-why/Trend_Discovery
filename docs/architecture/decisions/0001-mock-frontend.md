# 0001. 使用独立 React + Vite mock 前端预览趋势发现

- 日期：2026-10-12
- 状态：已采纳并已实现，仅适用于本次原型；正式产品技术选型待确认。

## 背景

用户明确要求先使用 mock 数据编写前端以查看效果，暂不接入真实数据。仓库此前只有需求文档，没有代码和运行入口。需求涉及多个榜单、详情、等级调整和多项报告，需能连续操作。

## 决策

- 使用 React + Vite 和普通 CSS，固定已安装依赖版本并保留 lock 文件。
- 所有样本集中于 [mockData.js](../../../src/mockData.js)，展示与交互位于 [App.jsx](../../../src/App.jsx) 和 [components.jsx](../../../src/components.jsx)，纯计算集中于 [domain.js](../../../src/domain.js)。
- 本地运行、系统字体和 SVG 示意图，不依赖远程图片、字体、API 或导出服务。
- 本次原型默认按近 7 天搜索增长排序，可切换近 1 天；图表窗口独立切换 7/14/30 天。
- 周增长比较近 7 天与前 7 天总量；日增长比较最近两日；榜单排名为本系统搜索增长榜，大盘商品排名另列。
- 同时命中等级阈值时爆发优先；人工等级只在页面会话内覆盖展示，保留系统判定证据。
- 相似商品采用预置关系和近 7 天点击/成交样本，不自动评价自家表现。
- 报告固定品类→款式→关键词分组，支持组内排序、项隐藏/恢复及内容区块隐藏；PDF 使用浏览器打印布局保存。

以上计算、持久化与报告细节属于原型工程默认，不能据此将 [PRD](../../../PRD.md) 的待决生产规则标为已确认。

## 替代方案

- 单页静态 HTML：部署更简单，但多个榜单与报告状态更难持续组织。
- 完整后端和 API：可以验证真实数据，但超出本次用户明确要求的 mock 预览范围。
- 服务端 PDF：可直接下载，但会增加后端或字体资源依赖；本次采用浏览器打印先验证内容与排版。

## 后果

原型可以独立安装、运行和构建，后续可保留组件结构替换数据来源。仍需 Node 环境；刷新会重置页面状态。打印窗口支持取决于浏览器，生产导出、真实数据和自动提醒需后续实现。数据口径与匹配规则仍按 [TODO](../../../TODO.md) 跟进。
